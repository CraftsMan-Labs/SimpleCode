Finally, review all changes through a **code cleanliness lens**.

Read every modified file and check for:

1. **Naming**: are variables, functions, classes named clearly and consistently with the codebase?
2. **Structure**: is the code organised logically? Are functions too long? Is responsibility split well?
3. **Duplication**: any copy-pasted logic that should be extracted?
4. **Dead code**: unused imports, unreachable branches, commented-out code left behind?
5. **Style consistency**: does new code match the existing codebase style? Indentation, quotes, line length?
6. **Documentation**: are public APIs documented where the codebase convention expects it?
7. **Simplification**: any overly complex logic that could be simpler?

For each finding, report:

```
### [CLEAN-001] Title
- **Severity**: Warning / Suggestion
- **File**: `path/to/file:line`
- **Issue**: What's wrong
- **Fix**: How to improve it
```
