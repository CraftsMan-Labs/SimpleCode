Rewrite the attack as an actionable fixer packet.

This reply becomes `adversarial/output.md`. The fixer is unattended and will
execute only what you list. Vague findings will be skipped or misapplied.

## Must-fix list

For every `critical` or `major` finding, write a numbered item with all four fields:

1. **id** — `F-01`, `F-02`, ...
2. **target** — exact file path(s)
3. **change** — the concrete edit to make (not "improve tests")
4. **verify** — the exact command the fixer must run to prove the fix

Minor findings go under **acceptable residuals** unless they block the ticket.

If there are no must-fix items, say so explicitly and do not invent work.

## Output

1. Attack summary
2. Must-fix before close (the numbered actionable list, or `none`)
3. Acceptable residuals
4. Final line:

```text
ADVERSARIAL STATUS: CLEAR
```

or

```text
ADVERSARIAL STATUS: FINDINGS
```

Use `CLEAR` only when the must-fix list is `none`.
