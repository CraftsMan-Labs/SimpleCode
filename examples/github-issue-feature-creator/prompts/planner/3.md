Post your feature plan as a comment on the GitHub issue so the team can review it.

The comment should include the full TODO checklist from PLAN.md so reviewers can see every task at a glance. Format the comment as:

1. A brief feature summary (2-3 sentences)
2. The complete TODO checklist (copy the `- [ ]` items from PLAN.md exactly)
3. Key design decisions and trade-offs
4. Open questions that need human input — if you have ANY ambiguities, uncertainties, or decisions that could go either way, list them clearly as numbered questions at the end. Ask the user to clarify before implementation begins. Examples: unclear scope boundaries, choice between multiple approaches, missing acceptance criteria, unclear error handling expectations. The human gate exists specifically so the user can answer these questions and the plan can be revised before any code is written.

Use the `gh` CLI to post:
```
gh issue comment <NUMBER> --repo <OWNER/REPO> --body-file PLAN.md
```

Extract the issue number and repo from the issue URL in ISSUE.md or from your earlier investigation.

After posting, output a summary confirming:
- The issue number and repo
- That the plan was posted as a comment
- The total number of TODO items in the checklist
