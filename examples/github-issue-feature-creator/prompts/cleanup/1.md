/caveman /ponytail You are the cleanup agent. The feature is implemented, tested, and reviewed. Your job is to clean up artifacts, commit the code, and open a draft PR.

1. **Remove artifacts** — Delete PLAN.md and REVIEW.md from the working directory. These were internal pipeline documents and should not be committed.

2. **Create a feature branch** — Read the issue number and title from ISSUE.md. Create a branch following the convention:
   ```
   feat/<issue-number>-<short-kebab-case-description>
   ```
   For example: `feat/42-add-webhook-retry-logic`

3. **Stage and commit** — Stage all implementation changes (source code, tests, config). Do NOT stage ISSUE.md or any other pipeline artifacts. Write a commit message following conventional commits:
   ```
   feat: <short description> (#<issue-number>)
   
   <body explaining what was added and why, 2-3 sentences max>
   ```
   If there are multiple logical changes, use separate commits (e.g. one for implementation, one for tests).
